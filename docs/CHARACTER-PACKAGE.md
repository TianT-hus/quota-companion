# 朝夕 · 桌宠与角色包

适用于朝夕 0.2.31（build 47）。项目展示形象为**蓝色礼裙**：透明人物轮廓、裙摆额度填充、独立额度文字，以及抛接蓝色手捧花动作。

![朝夕蓝色礼裙，周 50% 为合成示例](assets/zhaoxi-blue-gown.png)

这张 PNG 是展示图。完整分层角色包尚未包含在 0.2.31 公开下载中，首次启动仍使用内置基础形象。单张展示图无法还原完整分层和动画。

## 在应用中添加桌宠

进入“设置 → 外观 → 我的桌宠 → 新建”，选择：

- **从图片制作**：选择本地图片，按向导调整画布、额度区域与效果，命名保存；得到静态形象。
- **导入角色包**：选择包含 `character.json` 和全部 PNG 图层的文件夹，检查效果、命名保存，再选择使用。已有蓝色礼裙角色包可走此流程，包内动作会保留。

角色导入和图片制作均在本机处理。原始图片与来源文件夹不被覆盖；已保存角色使用独立 UUID 存入本地角色库。删除当前导入角色后会回到内置基础形象，恢复基础形象不会自动删除其他角色。

## 文件结构与版本

```text
角色名称/
  character.json
  base.png
  fill-mask.png
  details.png
```

| 格式 | 图层尺寸 | 用途 | 每张 PNG 上限 |
| --- | --- | --- | --- |
| v1 | 72 × 80 | 静态分层角色 | 256 KiB |
| v2 | 288 × 320 | 高清静态分层角色 | 256 KiB |
| v3 | 288 × 320 | 高清分层角色和 8 帧动作 | 256 KiB |
| v4 | 288 × 320 | 从图片制作的静态角色，可有不透明背景 | 512 KiB |

所有图层均需 alpha 通道、正向、单帧 PNG。同一包内尺寸一致。v1–v3 需要透明轮廓、可填充区域和受保护细节；v4 允许完全不透明的底图，填充和细节层可全透明。v4 需要朝夕 0.2.22 或更新版本。

- `base.png`：完整角色；零额度时仍显示。
- `fill-mask.png`：alpha 标出额度填充区域；不得越过底图轮廓或指定的上下填充边界。
- `details.png`：保护脸部、五官和其他原色细节，绘制在填充层上方；alpha 不得超过底图。

包导入不接受 ZIP、GIF、APNG、符号链接或可执行脚本。额外文件不会复制；导入会重新编码 PNG 并去除元数据。数字区域始终使用 **72 × 80 逻辑坐标**，高清版本校验时按 4 倍换算。

## 角色说明文件

`character.json` 上限 16 KiB，静态 v2 示例：

```json
{
  "version": 2,
  "name": "蓝色礼裙",
  "label": { "x": 12, "y": 49, "width": 48, "height": 23 },
  "fillTop": 40,
  "fillBottom": 79
}
```

包内名称为 1–40 个字符，不允许控制字符；应用编辑器还会按显示宽度检查新名称。数字区域完全位于 72 × 80 内且至少 28 × 22。填充边界满足 `0 ≤ fillTop < fillBottom ≤ 80`。上面的布局来自礼裙示例，其他角色应按自己的脸部、身体和衣服位置调整。

## v3 动作

在三张静止层之外，添加 `frame-0-base.png`、`frame-0-fill-mask.png`、`frame-0-details.png`，依此至 `frame-7`，共 27 张 PNG。manifest 将 `version` 设为 `3` 并增加：

```json
"animation": { "durationsMilliseconds": [375,375,250,375,375,375,375,500] }
```

必须有 8 个时长，每项 125–1000ms、为 125ms 的倍数，总计 3000ms。每一帧使用相同画布和逻辑布局；透明轮廓、填充区域与保护层都要校验。动作末帧与静止姿势应衔接自然。额度文字由应用独立绘制，不烘焙进角色图层。

在桌宠编辑中可管理兼容动作、启用状态与播放频率。悬停、拖动、打开详情、隐藏、休眠、锁屏及系统“减少动态效果”等状态会影响播放；角色包本身不能执行脚本。
