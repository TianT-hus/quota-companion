# 本地角色包 v1 / v2 / v3

在对话中提供人物或宠物照片，生成并确认角色预览后，整理为下列文件夹。应用不调用生成服务、不接收原始照片、不上传数据。人物与宠物使用同一种资源格式，生成结果仍需人工检查小尺寸辨识度。

```
角色名称/
  character.json
  base.png
  fill-mask.png
  details.png
```

三个图层都必须是具有 alpha 通道的静态 PNG、方向为正向，每张不超过 256 KiB。v1 三层均为 72×80 像素；v2 三层均为 288×320 像素（需要应用 0.1.12+）。坐标原点为左上，两个版本的数字区域和填充边界都使用 72×80 逻辑坐标。v2 校验像素区域时乘以 4。不支持 ZIP、符号链接、动画或可执行脚本；额外文件不会复制。导入重新编码 PNG，保留对应分辨率并剥离元数据。

- `base.png`：完整角色，带透明外轮廓；零额度也显示完整形象。
- `fill-mask.png`：用 alpha 标注允许着色的身体区域；不透明处参与额度填充，透明处不染色。其 alpha 不得超过原图对应像素的 alpha。
- `details.png`：原色脸部、五官和需要保护的细节，其他区域透明，绘制在填充层之上。alpha 不得超过原图对应像素。
- 三层轮廓必须对齐；数字区域不要盖住脸。填充遮罩的非透明像素必须位于 fillTop（含）和 fillBottom（不含）之间。

`character.json` 示例（文件上限 16 KiB）：

```json
{
  "version": 1,
  "name": "我的像素角色",
  "label": { "x": 12, "y": 40, "width": 48, "height": 24 },
  "fillTop": 32,
  "fillBottom": 77
}
```

名称 1–40 个字符，不允许控制字符。数字区域完全位于 72×80 内，至少 28×22；上下填充边界满足 0 ≤ fillTop < fillBottom ≤ 80。每个角色需单独安排这些区域，上述示例不代表所有人物或宠物的最佳位置。

高清包使用相同结构，将 `version` 设置为 2，并提供 288×320 分层。不要放大旧 72×80 素材冒充高清；从确认后的高分辨率母版重新制作。旧 v1 包仍可读取，无需迁移。运行时按显示档位和屏幕像素倍率直接从源图生成适配纹理，最多缓存 16 个配色／尺寸组合。文字始终独立绘制。

导入路径：设置 → 外观 → 桌宠形象 → 导入角色包。仅校验和本地保存成功后切换。导入资源以独立 UUID 保存于应用数据目录 `Characters/`，选中 ID 保存为 `character.selected.v1`；原有宠物路径、默认猫咪和用户照片不覆盖。恢复内置猫咪不会删除导入资源。

v1/v2 为静态分层素材，没有固定猫眼位置的眨眼动画。身体填充、告警色、胸前文字及离线标记继续工作。首次启动找不到已选资源时显示内置猫咪并在设置中提示，不删除历史选择。

## v3 间歇动作（0.2.3+）

保留上述三张 288×320 静止层，并增加 `frame-0-base.png`、`frame-0-fill-mask.png`、`frame-0-details.png`，依此至 frame-7。共 27 张 PNG；每层使用相同尺寸、坐标及安全限制。这里的动作是多张静态 PNG 离散切换，不接收 GIF、APNG、脚本或任意路径。

manifest 的 version 为 3，并增加：

```json
"animation": { "durationsMilliseconds": [375,375,250,375,375,375,375,500] }
```

必须有 8 个时长，每项 125–1000ms 且是 125ms 的倍数，总计 3000ms。每一帧校验透明轮廓、填充范围及保护层，不合格不切换当前角色。静止图与首尾帧应由作者保持一致。

动作等待 25–40 秒后播放一次，使用 Core Animation 离散图层；数字不参与动作。悬停、拖动、打开详情、隐藏、休眠、锁屏及减少动态效果均停止，恢复后重新等待。外观中的动作开关保存在独立键，不修改旧角色设置。动态角色每帧仅缓存一个配色／尺寸组合，切换角色释放纹理缓存；静态角色仍采用 16 组合上限。

私人照片衍生的动作图层仅保存在本地资源包，不进入公共应用包、插件或仓库。
